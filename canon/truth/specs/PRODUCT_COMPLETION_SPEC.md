# PRODUCT COMPLETION SPEC

## Purpose
Turn structurally correct systems into finished products.

## Required components
- complete end-to-end flows
- coherent UX language
- executive/operator/builder-specific surfaces
- good defaults
- speed perception optimization
- operator efficiency features
- robust error/loading/permission handling
- polished onboarding and status surfaces

## Inputs
- product intent
- user role
- workflow graph
- quality bar

## Outputs
- finished flows
- role-adapted experiences
- polished user-visible surfaces

## Invariants
- “done” means works, feels coherent, and reduces friction
- product quality is not optional after architecture correctness

## Tests required
- end-to-end task completion
- role-specific UX pass
- loading/error/permission state pass
- speed/perceived responsiveness pass

## Done when
- the system feels like a finished product, not just a correct architecture
